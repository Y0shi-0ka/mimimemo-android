# ミミメモ

情報工学専門実験・演習B Android演習の課題アプリです。会話から自動で ToDo をつくる、学生向けのアプリです（仕様は第2回レポート）。

マイクのボタンを押すと聞き取りを始め、画面を閉じても止めるまでバックグラウンドで会話を文字に起こします（動いている間は「聞き取り中」の通知が出ます）。文はメモリにためて5分ごとにまとめて調べ、ToDo になりそうなものを1枚ずつカードで出します。右に払ったものだけを保存します。音声も文字起こしも保存しません。

## 画面

| # | 画面 | クラス |
|---|---|---|
| ① | ToDo 一覧（期限順） | `MainActivity` |
| ② | 聞き取り（文字起こし表示） | `ListeningActivity` |
| ③ | ToDo 候補の詳細ダイアログ（候補カードをタップしたとき） | `ListeningActivity#showCandidateDialog` |
| ④ | ToDo 編集 | `TodoEditActivity` |
| ⑤ | 今日のまとめ | `SummaryActivity` |
| ⑥ | 設定（キーワード辞書・タグ） | `SettingsActivity` |

① の下のマイクのボタンで ②、カードのタップで ④、メニューから ⑤ と ⑥ に移ります。

アプリを開かずに使う入口もあります。

| 入口 | できること | クラス |
|---|---|---|
| クイック設定のタイル | 押すと聞き取りを始める・止める。聞き取り中は点灯（#85） | `ListeningTileService` |
| ホーム画面ウィジェット | 期限の近い ToDo 3件と、聞き取りを始めるマイク。① のメニュー「ホーム画面に置く」から置けます（#97） | `TodoWidget` |
| 共有メニュー「ミミメモ」 | ほかのアプリの文章（LINE・メールなど）を ToDo 候補のカードにする。聞き取りは始めません（#93） | `SharedText`、別名 `.ShareTarget` |
| 聞き取り中の通知 | 先頭の候補を「追加」「しない」で決める・「停止」（#83） | `ListeningService` |
| 朝の通知 | 毎朝（7時・8時・9時から選べる）、期限切れ・今日・明日の ToDo があれば知らせる（#100・#125） | `MorningReminder` |

「毎週月曜にゴミ出し」「毎日薬を飲む」「毎月25日に家賃」のような繰り返しの ToDo は、完了にすると期限が次の日付へ進みます（編集画面で 繰り返し しない／毎日／毎週／毎月 を選べます、#107）。

一覧のいちばん下の「完了 n」を押すと、完了した ToDo（新しい順に50件）が開き、丸を押し直すと未完了に戻せます（#87）。

## 設計の方針

- **無駄なものは表示しない**：説明文や補助の数字は常時出さず、必要な状態のときだけ出します。聞き取り画面は、聞き取れている間は状態・文字起こし・候補・停止ボタンだけです（#19、#20）
- **文字入力をなくす**：一覧に入力欄はなく、マイクのボタンだけです。文字を打つのは聞き間違いを直すとき（編集）とキーワード辞書だけです（#45）
- **バックグラウンドで常時聞き取る**：聞き取りは前面サービス `ListeningService` が受け持ち、戻る・画面を閉じるでは止まりません。止めるのは停止ボタンか通知の「停止」です。画面は点けたままにしません（#44）
- **操作の手間を少なく**：追加・完了・削除はスワイプで済ませ、別画面・ダイアログは詳細を直すときだけ使います。取り消しは「元に戻す」で行います（#12）
- **まとめて調べる**：文は5分ためてから調べるので、会話の途中で何度もカードが割り込みません。前後の文から期限を補えます（「来週月曜が提出の日です」「スライド作っといて」→ スライドの期限が来週月曜）。急ぐときは「今まとめる」（#36、#39）
- **省電力**：聞き取り中も画面は点けたままにしません。認識は連続認識でマイクを開けたまま区切りごとに受け取り、1文ごとに起動し直しません（#42）。常時動くアニメーションや定期的な確認は置きません
- **会話を外に出さない**：端末内の音声認識だけを使います。使えない端末では、通常の認識（音声がサーバに送られることがある）には切り替えません（#9）

## 操作

| 画面 | 右スワイプ | 左スワイプ | タップ |
|---|---|---|---|
| ① 一覧 | 完了 | 削除 | 編集画面 ④（長押しで 明日／来週月曜／期限なし に延ばす、#131） |
| ② 聞き取りの候補カード | 追加 | 追加しない | 詳細ダイアログ ③ |

① の下の大きなマイクで聞き取りを始めます。聞き取り中や決めていない候補があるときは、マイクの上に「聞き取り中・候補n件」の札が出て、押すと ② を開きます。一覧のスワイプは `SwipeActions`、候補カードは `CandidateStackView` です。候補カードは指に合わせて傾き、幅の3割を超えて離すか素早く払うと決まります。下の ✕ / ✓ ボタンでも同じです（#33）。

## 処理を受け持つクラス

| クラス | 役割 |
|---|---|
| `SpeechController` | 端末内の音声認識（`createOnDeviceSpeechRecognizer`、Android 12 以降）。無音で止まると自動で再開します。日本語モデルがなければダウンロードを頼み、入ったら自動で始めます（#14）。キーワード辞書の言葉を語彙のヒントとして認識器に渡します（#22） |
| `TodoExtractor` | キーワードで文を絞り込み、ToDo のタイトル・期限・タグを取り出します |
| `ListeningService` | 前面サービス。画面を閉じても認識・5分まとめ・候補の抽出を続け、「聞き取り中」の通知を出します（#44） |
| `ListeningHub` | 聞き取りの状態・文字起こし・候補をサービスと画面で共有します。文字起こしは保存しません |
| `CandidateStore` | 決める前の候補（やること・期限・タグ・元の発言）だけを端末に残し、アプリが止められても消えないようにします（#55） |
| `ChoiceChips` | 期限・タグを1タップで選ぶ札（#47） |
| `DueSections` | 一覧を期限切れ・今日・明日・今週・来週以降・期限なしで区切ります（#49） |
| `RecognizedText` | 認識結果の空白を取り除き、複数の候補からキーワードを含むものを選びます（#42） |
| `SentenceBatch` | 聞き取った文をメモリにためて取り出し、期限のない候補に前後の文の期限を補います（#36） |
| `CandidateStackView` | 候補カードの束。左右に払って追加する・しないを選びます（#33） |
| `CandidateDeduper` | 聞き取り中、同じ内容の候補を続けて出さないようにします |
| `LocalLlm` | 端末内の小さな AI（LiteRT-LM）。5分まとめのときだけ読み込み、終わったら外します。メモリが足りなければ使いません（#68） |
| `AiTaskPrompt` | AI への問いと、答え（`番号|やること|期限の言葉|タグ`）の読み方 |
| `DateParser` | 「明日」「来週月曜」「15日まで」「11/20」「十一月二十日」などを日付に変換します |
| `TodoDbHelper` | SQLite の `todos` テーブル |
| `ReminderSpeaker` | TextToSpeech での読み上げ。明日が期限の ToDo は、その日はじめて一覧を開いたときに1回だけ読み上げます（#8） |
| `MorningReminder` | 毎朝（設定で 7時・8時・9時・しない を選べる、初期値8時）から1時間の間に、期限切れ・今日・明日の ToDo を通知します（#100・#125） |
| `TodoWidget` | ホーム画面ウィジェット。ToDo を変えたとき（`TodoDbHelper` の書き込み）に描き直します（#97） |
| `SharedText` | 共有された文章を、聞き取りと同じ流れで候補にします（#93） |
| `KeywordStore` | キーワード辞書（SharedPreferences） |
| `TagStore` | 自分で足したタグ（科目名など）。文中にその名前があれば、そのタグを付けます（#10） |

## 端末内の AI（文脈から ToDo を選ぶ）

5分ごとのまとめでは、ルールと端末内の小さな AI の両方で調べ、どちらかが拾った文を候補にします（#68）。会話は端末の外に出しません。AI のモデルがないとき・メモリが足りないときは、ルールだけで動きます。

- 実行環境：LiteRT-LM（`com.google.ai.edge.litertlm:litertlm-android:0.19.1`）
- 既定のモデル：[Qwen2.5-1.5B-Instruct](https://huggingface.co/litert-community/Qwen2.5-1.5B-Instruct)（`Qwen2.5-1.5B-Instruct_multi-prefill-seq_q8_ekv4096.litertlm`、約1.6GB、Apache-2.0）。動かすときに約 2.2GB のメモリを使うので、メモリ 6GB 以上・空き 2.5GB 以上の端末で使います
- モデルの入れ方：`.litertlm` を端末に置き（ダウンロードフォルダなど）、設定画面（キーワードとタグ）の「モデルを取り込む」で選ぶ。アプリはインターネットを使わない（#74）。「外す」でルールだけに戻せる
- モデルの置き場所：端末の `Android/data/jp.mimimemo/files/models/`（`.litertlm` を1つ置く）

```sh
curl -L -o model.litertlm https://huggingface.co/litert-community/Qwen2.5-1.5B-Instruct/resolve/main/Qwen2.5-1.5B-Instruct_multi-prefill-seq_q8_ekv4096.litertlm
adb shell mkdir -p /sdcard/Android/data/jp.mimimemo/files/models
adb push model.litertlm /sdcard/Android/data/jp.mimimemo/files/models/
```

キーワード辞書の画面の上に、AI を使っているかどうかが出ます。

### 評価セット

`eval/conversations.json` に会話例と正解を置いています（#71）。ルールは `TodoEvalTest`、AI は `eval/run_llm_eval.py` で同じ例を流します。2026-11-20 の結果：

| 方式 | 適合率 | 再現率 |
|---|---|---|
| ルールだけ | 0.79 | 0.65 |
| AI（Qwen2.5-1.5B）だけ | 0.63 | 0.74 |
| ルールと AI のどちらか（採用） | 0.63 | 0.96 |
| AI（Qwen3-0.6B）だけ | 0.43 | 0.39 |

上の表は最初の16例での比較。その後ルールを直し（#80・#71）、例を54件に増やした。足した18例を初めて流したときは全体で適合率 0.96・再現率 0.78 に下がり、それを見て直したあとは 0.96・0.86。直すときに一度も見ていない20例だけでは 1.00・0.74（足した18例は直すときに見たので、見ていない例には数えない）。AI は PC の空きが足りず、54例ではまだ流していない。

```sh
python -m venv llmenv && llmenv/Scripts/pip install litert-lm-api==0.19.2
./gradlew testDebugUnitTest --tests jp.mimimemo.TodoEvalTest   # ルールの結果を app/build/eval-rules.json に書く
llmenv/Scripts/python eval/run_llm_eval.py model.litertlm      # AI と、組み合わせの成績
```

## 実機に入れる

1. 端末の 設定 → デバイス情報 →「ビルド番号」を7回タップして、開発者向けオプションを出す
2. 設定 → システム → 開発者向けオプション →「USB デバッグ」をオンにする
3. USB でパソコンにつなぎ、端末に出る「USB デバッグを許可しますか」で許可する
4. パソコンで次を実行する

```sh
adb devices                                                # 端末が device と出ることを確かめる
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`adb` は Android SDK の `platform-tools` にあります（Windows なら `%LOCALAPPDATA%\Android\Sdk\platform-tools`）。

## 実機での確認項目

聞き取りには Android 12 以降と、端末内の音声認識（Pixel では Android System Intelligence）が必要です。

| 機能 | 操作 | 期待する結果 |
|---|---|---|
| 聞き取り（初回） | マイクのボタンを押す | マイクの許可を聞かれる。日本語モデルがなければダウンロードの確認が出て、終わると自動で「聞き取り中」になる |
| 聞き取り | 「来週月曜までにレポート提出してください」と話し、「今まとめる」を押す（押さなければ5分後） | 文が色付きになり、カードが出る（レポート提出する・来週月曜の日付・授業） |
| 聞き取り | 「来週月曜が提出の日です」「スライド作っといて」と続けて話し、「今まとめる」 | カードは「スライド作る・来週月曜」の1枚だけ |
| 聞き取り | 「今日はいい天気ですね」と話す | 文字起こしだけ出て、候補は出ない |
| 候補 | カードを右へ払う／左へ払う | 追加される／追加しない。どちらも「元に戻す」で取り消せる |
| 停止 | 話している途中で停止ボタン | 最後の文まで文字になってから止まる（#53）。決めていないカードがあれば閉じずに「閉じる」に変わる |
| 候補を残す | 候補がある状態でアプリを強制停止して開き直す | 一覧に「候補n件」が残っている（#55） |
| 編集 | ToDo をタップし、期限の「明日」を押して戻る | 保存ボタンなしで期限が明日になる（#47） |
| 常時 | 聞き取り中に戻る・ホームに戻る | 通知に「聞き取り中」が残り、聞き取りが続く。通知の「停止」で止まる |
| リマインド | 「読み上げ」を押す | 明日が期限の ToDo を読み上げる |
| まとめ | メニュー →「今日のまとめ」 | 今日登録した ToDo と元の発言が並ぶ |
| キーワード辞書 | メニュー →「キーワード辞書の設定」で「やっといて」を追加 | 「スライドやっといて」が候補になる |

### 聞き取りが始まらないとき

聞き取り画面の状態の下に、理由とできる操作が出ます。

| 表示 | 意味 |
|---|---|
| マイクが使えません | マイクを許可していない。「マイクを許可する」を押す |
| 日本語モデルが必要 | モデルのダウンロードを取りやめた。「ダウンロードする」を押す |
| ダウンロード中 | モデルを入れている。終わると自動で始まる |
| 手入力のみ | この端末は端末内の音声認識に対応していない。下の欄に文を打つと同じ流れで使える |

くわしい原因は Logcat で追えます。認識した文そのものはログに出しません。

```sh
adb logcat -s MimiMemo
```

| ログ | 意味 |
|---|---|
| `start sdk=… onDevice=false` | 端末内の音声認識がない（手入力のみになる） |
| `onError code=13` | 日本語モデルがない |
| `onError code=7` / `code=6` | 無音。そのまま次を聞くので異常ではない |
| `onError code=9` | マイクの許可がない |
| `model: installed=… pending=…` | モデルの状態（pending はダウンロード中） |

## エミュレータで音声を確かめる

エミュレータ（API 35、Google Play 入りのイメージ）でも端末内の音声認識が動きます。日本語モデル（約 50MB）を入れたあと、パソコンのマイクをつなぎます。

```sh
adb emu avd hostmicon     # パソコンのマイクをエミュレータにつなぐ
adb emu avd hostmicoff    # 確認が済んだら切る（部屋の声を拾い続けるため）
```

## デバッグ版で候補カードを試す

adb では日本語を打てないので、デバッグ版だけ、聞き取った文の代わりに文を渡せます（リリース版には入りません）。

```sh
adb shell am start -n jp.mimimemo/.ListeningActivity --esa jp.mimimemo.debug.SENTENCES 来週月曜が提出の日です,スライド作っといてね
```

開いたら「今まとめる」を押すとカードが出ます。
